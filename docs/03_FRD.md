## 0. 이 문서의 전제

| # | 전제 |
|---|---|
| 0-1 | **클라이언트 검증은 UX 보조일 뿐이며, 서버 검증이 유일한 권위다 (R3).** 본 문서 2장의 검증 규칙은 클라이언트와 서버에 **문자 그대로 동일하게** 적용된다. 두 구현은 같은 Zod 스키마 하나를 공유한다. 클라이언트 검증을 통과했다는 사실은 서버가 요청을 받아들이는 근거가 되지 않으며, 서버는 원본 body를 사용하지 않고 파싱 결과만 사용한다. |
| 0-2 | 시안에 있으나 PRD에 없는 요소는 버리지 않고 기능으로 정의한 뒤 **`PRD에 없음`**으로 표시했다. |
| 0-3 | PRD 제외 범위(예약·결제·실시간 가격 보장·지도 연동·로그인)에 해당하는 요소는 **기능으로 정의하지 않았다.** 시안 작성 단계에서 해당 동선을 의도적으로 배제했으므로 삭제된 항목은 없다. |
| 0-4 | 모션·인터랙션도 기능이다. 완료 조건은 "코드를 작성했다"가 아니라 **브라우저에서 관찰 가능한 문장**으로 쓴다. |
| 0-5 | 금액·시간은 데이터 모델의 추정 객체(`confidence` + `basis` + `verifyHint`)로만 표현된다. 정적 푸터 문구로 대체하지 않는다 (R1). |

## 2. 입력 항목

### 2-1. 선택지 상수

모든 선택지는 `lib/constants/options.ts` 한 곳에 정의하고 클라이언트 UI와 서버 Zod 스키마가 **같은 배열을 참조한다.** 모바일과 데스크톱의 선택지가 완전히 동일함을 구조적으로 보장한다 (R4 · S10).

각 항목은 `{ value, label, hint }` 형태다. `hint`는 화면의 보조 설명이자 프롬프트에 전달되는 조건 설명으로 함께 쓰인다.

| 그룹 | 개수 | `value` | 한국어 `label` |
|---|---|---|---|
| `TRAVEL_STYLES` | **9** | `healing` / `nature` / `food` / `culture` / `photo` / `activity` / `shopping` / `city` / `family` | 힐링·휴식 / 자연·풍경 / 미식 / 역사·문화 / 사진·뷰맛집 / 액티비티 / 쇼핑 / 도시 산책 / 가족 여행 |
| `FOOD_LIKES` | **8** | `local` / `seafood` / `meat` / `vegetarian` / `cafe` / `street` / `fine` / `noodle` | 현지식 / 해산물 / 고기 / 채식 위주 / 카페·디저트 / 길거리 음식 / 분위기 좋은 곳 / 면요리 |
| `SPICE_LEVELS` | **4** | `none` / `mild` / `medium` / `hot` | 안 매움 / 약간 / 보통 / 매운 것 좋아함 |
| `AVOID_OPTIONS` | **8** | `long_walking` / `crowded_area` / `early_start` / `late_night` / `long_transfer` / `water_activity` / `height` / `driving` | 많이 걷기 / 사람 많은 곳 / 이른 아침 일정 / 늦은 밤 일정 / 긴 이동 / 물놀이·수상활동 / 높은 곳 / 직접 운전 |
| `BUDGET_SCOPES` | **2** | `total` / `per_person` | 전체 총액 / 1인당 |

`z.enum()`에 넘길 값 튜플(`TRAVEL_STYLE_VALUES` 등)은 같은 파일에서 `values()` 헬퍼가 파생시킨다. **선택지를 추가·삭제하면 UI와 검증 스키마가 동시에 바뀐다.**

입력 제한도 같은 파일의 `LIMITS` 상수 하나에서 나온다.

| 상수 | 값 | 상수 | 값 |
|---|---|---|---|
| `destinationMin` / `destinationMax` | 1 / 40 | `stylesMax` | 5 |
| `tripDaysMin` / `tripDaysMax` | 1 / 7 | `foodLikesMax` | 5 |
| `adultsMin` / `adultsMax` | 1 / 20 | `avoidMax` | 5 |
| `childrenMax` | 20 | `avoidIngredientsMax` | 100 |
| `infantsMax` | 10 | `notesMax` | 300 |
| `partyTotalMax` | 20 | `bodyBytesMax` | 8 × 1024 |
| `budgetMin` / `budgetMax` | 0 / 100,000,000 | | |

### 2-2. 입력 항목 표

검증 규칙은 **클라이언트와 서버에 동일하게 적용되며, 서버 판정이 권위를 갖는다 (R3).** 요청 본문은 관련 필드를 묶은 **중첩 객체**다.

| 항목명 | 필드 경로 | 필수 | 형식 | 검증 규칙 | 기본값 |
|---|---|---|---|---|---|
| 여행지 | `destination` | ✅ | 문자열 | `sanitize` (제어문자·꺾쇠 제거, 연속 공백 축약, 양끝 공백 제거) 후 **1~40자**. URL 형태 거부 | `''` |
| 여행 시작일 | `startDate` | ✅ | `YYYY-MM-DD` | 형식 일치 + 실재하는 날짜 + **오늘 이후** + **2년 이내** | `''` |
| 여행 종료일 | `endDate` | ✅ | `YYYY-MM-DD` | 형식 일치 + `endDate >= startDate` + **총 기간 1~7일**(양끝 포함) | `''` |
| 성인 수 | `partySize.adults` | ✅ | 정수 | **1 ~ 20** | `2` |
| 아동 수 | `partySize.children` | ✅ | 정수 | **0 ~ 20** | `0` |
| 유아 수 | `partySize.infants` | ✅ | 정수 | **0 ~ 10** | `0` |
| 인원 합계 | (파생) | ✅ | 정수 | 세 값의 합 `<= 20` | `2` |
| 예산 금액 | `budget.amount` | ✅ | 정수 | **0 ~ 100,000,000** (원) | `0` |
| 통화 | `budget.currency` | ✅ | 리터럴 | `'KRW'` 고정 | `'KRW'` |
| 예산 기준 | `budget.scope` | ✅ | 열거 | `total` / `per_person` | `'total'` |
| 여행 스타일 | `styles` | ✅ | 문자열 배열 | 각 원소가 `TRAVEL_STYLE_VALUES`에 존재 · **1개 이상 5개 이하** | `[]` |
| 음식 선호 | `foodPreference.likes` | — | 문자열 배열 | 각 원소가 `FOOD_LIKE_VALUES`에 존재 · **0~5개** | `[]` |
| 못 먹는 재료 | `foodPreference.avoidIngredients` | — | 문자열 | `sanitize` 후 **100자 이하** | `''` |
| 맵기 | `foodPreference.spiceLevel` | — | 열거 | `SPICE_LEVEL_VALUES` 중 하나 | `'medium'` |
| 피하고 싶은 것 | `avoid` | — | 문자열 배열 | 각 원소가 `AVOID_VALUES`에 존재 · **0~5개** | `[]` |
| 추가 요청 | `notes` | — | 문자열 | `sanitize` 후 **300자 이하** · **URL 형태 거부** | `''` |
| 로케일 | `locale` | — | 리터럴 | `'ko-KR'` 고정 | `'ko-KR'` |

> **초기 설계안과 달라진 규칙 세 가지** — ① 시작일에 **과거·2년 초과 미래** 제한이 추가되었다. 실수 입력을 막고, 모델이 존재하지 않는 시점의 일정을 지어내는 것도 함께 막는다. ② `notes`에도 URL 거부가 적용된다. 자유 입력 전체가 같은 기준을 받아야 한다. ③ 요청 본문이 평탄한 형태가 아니라 `partySize`·`budget`·`foodPreference` 중첩 객체다. 그룹 단위로 오류 메시지가 붙어 폼 UI와 맞는다.

### 2-3. 요청 단위 제약 (서버 전용)

클라이언트 UI에 대응 항목이 없고 서버에서만 판정한다.

| 제약 | 값 | 위반 시 |
|---|---|---|
| 요청 body 크기 | **8KB 초과 시 JSON 파싱 전에 거부** | `413 PAYLOAD_TOO_LARGE` |
| 요청 빈도 | **IP당 10분에 5회** | `429 RATE_LIMITED` |

#### 2-4-1. Zod 기본 문구의 한국어화 — 영어 유출 차단

명시적 메시지를 붙이지 않은 규칙(타입 불일치, enum 위반 등)은 **Zod의 기본 영어 문구가 그대로 사용자 화면에 노출된다.** 실제로 확인된 유출 예: `"Invalid input: expected object, received undefined"`.

두 겹으로 막는다.

| # | 장치 | 위치 |
|---|---|---|
| 1 | `z.config(ko())` — `zod/locales`의 한국어 로케일을 전역 적용 | `lib/validation/zod-locale.ts` |
| 2 | 최상위 필수 필드에 명시적 한국어 메시지를 직접 부착 | `lib/validation/plan-request.ts` |

`plan-request.ts`가 `zod-locale`을 **첫 줄에서** import하므로, 스키마가 정의되기 전에 로케일이 설정된다. 검증 경로에서는 항상 적용된 상태가 보장된다.

**완료 조건**: 어떤 잘못된 입력을 보내도 화면과 응답의 `fields`에 영어 문장이 **0건**이다.

### F-05 여행 스타일 선택

| 항목 | 내용 |
|---|---|
| 사용자 행동 | 9개 칩 중 원하는 것을 누른다. 다시 누르면 해제된다. |
| 입력값 | `styles` — `TRAVEL_STYLES`의 `value` 배열 |
| 처리 규칙 | 이미 5개가 선택된 상태에서 6번째를 누르면 선택되지 않고 "여행 스타일은 최대 5개까지 선택할 수 있습니다."를 그룹 아래에 표시한다. 선택 개수를 "3/5 선택됨"으로 항상 보인다. 칩 목록은 `TRAVEL_STYLES` 배열을 그대로 렌더하므로 390px과 1440px에서 개수·순서가 동일하다. |
| 출력값 | 선택된 키 배열과 개수 라벨. |
| 오류 상태 | 0개인 채로 제출 → "여행 스타일을 하나 이상 골라 주세요." · 6개 시도 → 상한 안내(선택은 반영되지 않음) |
| 완료 조건 | 390px과 1440px에서 스타일 칩 개수가 각각 **9개**로 같다. 6개째 칩을 누르면 선택되지 않고 상한 안내가 보인다. |

> **선택 누락 — 검증 중 발견한 실제 결함.** 칩을 빠르게 연속으로 누르면 일부 선택이 반영되지 않았다. 상태 갱신 함수가 렌더 시점의 값을 닫아 잡아(stale closure) 같은 스냅샷 위에 덮어썼기 때문이다. `PlanForm`의 `patch()`가 **함수형 갱신자**(`(prev) => Partial<...>`)를 받도록 바꿔 항상 최신 상태 위에서 계산한다. 칩 토글·증감 버튼 등 이전 값에 의존하는 모든 갱신에 적용된다.
>
> 추가 완료 조건: 스타일 칩 5개를 **최대한 빠르게** 연속으로 누르면 5개가 모두 선택되고 카운터가 "5/5 선택됨"을 보인다.

### F-09 입력 검증 및 인라인 안내

| 항목 | 내용 |
|---|---|
| 사용자 행동 | 필드를 벗어나거나 [여행 계획 만들기]를 누른다. |
| 입력값 | 폼 전체 상태 |
| 처리 규칙 | `blur` 시 해당 필드만, 제출 시 전체를 2장 규칙으로 검사한다. **검사에 실패하면 네트워크 요청을 보내지 않는다.** 제출 실패 시 첫 번째 오류 필드로 포커스를 옮긴다. 오류 필드마다 색 + ⚠ 아이콘 + 문구 3중으로 표시하고 `aria-invalid="true"`, `aria-describedby`를 연결한다. 검증 실패를 이유로 제출 버튼을 비활성화하지는 **않는다** — 눌러서 이유를 보게 한다. 다만 **하이드레이션 완료 전에는 비활성화한다**(아래 참고). |
| 출력값 | 필드별 오류 문구 집합. |
| 오류 상태 | 이 기능 자체가 오류 표시 기능이다. 검증 로직 예외 발생 시 제출을 막고 "입력을 다시 확인해 주세요."를 폼 상단에 표시한다. |
| 완료 조건 | 여행지만 입력하고 [여행 계획 만들기]를 누르면 **네트워크 탭에 `/api/plan` 요청이 나타나지 않고**, 일정 필드 아래에 "여행 시작일과 종료일을 선택해 주세요."가 뜨며, 포커스가 시작일 필드로 이동한다 (S3). 어떤 오류 문구에도 영어 문장이 없다 (2-4-1). |

> **하이드레이션 가드 — 검증 중 발견한 실제 결함.** JavaScript가 붙기 전에 제출 버튼을 누르면 브라우저가 **폼을 네이티브 제출**해 GET 내비게이션이 일어나고 **입력값이 전부 사라졌다.** `onSubmit`의 `preventDefault()`는 핸들러가 붙은 뒤에만 동작하기 때문이다. `PlanForm`이 `hydrated` 상태를 두어 **마운트 전까지 제출 버튼을 비활성화한다.**
>
> 추가 완료 조건: 페이지 로드 직후(JS 실행 전) 제출 버튼을 눌러도 **주소가 바뀌지 않고 입력값이 유지된다.**

| 항목 | 내용 |

| 사용자 행동 | 데스크톱에서 Hero를 보고, 3D 오브젝트를 클릭한다. |

### F-38 능력 판정과 모션 저감 폴백

| 항목 | 내용 |
|---|---|
| 사용자 행동 | OS의 "동작 줄이기"를 켜거나, 창 크기를 768px 경계 너머로 바꾼다. |
| 입력값 | `matchMedia` 조건 |
| 처리 규칙 | `gsap.matchMedia()`로 `full`(≥768px + no-preference) / `mobile`(<768px) / `calm`(reduce) 세 컨텍스트를 정의한다. 조건이 바뀌면 **이전 컨텍스트가 자동 revert**되므로 창 크기를 왔다 갔다 해도 트윈이 누적되지 않는다. **모든 능력 판정은 `useEffect` 안에서만 한다** — 서버는 항상 `calm` 변형(포스터·정적 레이아웃·최종 상태)을 렌더하고 클라이언트가 마운트 후 승격한다. CSS 쪽에서도 `@media (prefers-reduced-motion: reduce)`로 duration 토큰을 0/150ms로 치환해 이중으로 건다. `calm`에서 해제되는 것: pin·scrub·배경 사진 전환/Ken Burns·Canvas·y 이동·스태거·루프. **유지되는 것: 모든 콘텐츠·문구·순서·개수.** |
| 출력값 | 조건에 맞는 모션 변형. |
| 오류 상태 | `matchMedia` 미지원(구형) → `calm` 변형으로 안전하게 떨어진다. |
| 완료 조건 | OS 동작 줄이기를 켜고 새로고침하면 Hero에 3D가 없고 배경 사진이 첫 장에서 정지해 있으며, 스크롤해도 pin이 걸리지 않고, 결과 화면의 모든 블록·문구·항목 개수가 모션 켠 상태와 **완전히 동일하다** (S12). 창을 1440px→390px→1440px로 바꿔도 애니메이션이 겹쳐 보이지 않는다. |

### F-40 Hero 배경 사진 시퀀스 (영상 대체)

> **설계 변경 기록**: 원래는 오픈소스 배경 영상 + 자동재생 거부 폴백이었다.
> 빌드 환경에서 Pexels 영상 CDN이 403, Pixabay 영상 경로가 404로 접근 불가해
> 영상을 확보하지 못했고(`public/assets-manifest.json`의 `notObtained` 참고),
> 같은 목적(움직이는 첫인상)을 사진 시퀀스로 구현했다.
> 결과적으로 **자동재생 거부라는 실패 경로 자체가 사라졌다.**

| 항목 | 내용 |
|---|---|
| 사용자 행동 | Hero를 본다. 별도 조작이 없다. |
| 입력값 | 자체 호스팅한 Pexels 사진 3장 (`public/images/hero-0{1,2,3}-*.jpg`) |
| 처리 규칙 | `components/hero/HeroMediaLayer.tsx`가 5.2초 간격으로 장을 바꾸고 1.6초 교차 디졸브한다. 활성 장에는 CSS `hero-kenburns-drift` 애니메이션(9초, scale 1.04→1.16 + 미세 패닝)이 붙는다. 첫 장은 `priority`로 선로드되어 LCP 경로에 들어간다. z=0 레이어의 스크럽 트윈(scale·blur·opacity)은 이 컨테이너에 그대로 적용된다. `animate=false`(모션 저감)면 첫 장에서 정지하고 전환 시간을 0ms로 둔다. |
| 출력값 | 움직이는 사진 기반 Hero. 오디오 없음. |
| 오류 상태 | 사진 로드 실패 시 `next/image`가 빈 영역을 남기지만, 그 위의 스크림과 카피는 독립 레이어라 가독성이 유지된다. 오류 문구를 띄우지 않는다. |
| 완료 조건 | Hero 배경이 5초 남짓 간격으로 바뀌며 천천히 확대된다. 모션 저감 설정에서는 첫 장에서 멈추고 카피가 또렷하게 읽힌다. 어떤 경우에도 오류 메시지가 없다. |
| 영상 복원 시 | `HeroMediaLayer.tsx`의 `HERO_FRAMES`를 `<video>`로 교체하고, 출처·라이선스를 `public/assets-manifest.json`에 추가한다. 그때 자동재생 거부 폴백을 이 문서에 다시 정의해야 한다. |

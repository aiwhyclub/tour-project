## 2. 포커스 표시 — QA 에서 가장 큰 결함

`design/screen-states.md` §7 과 `footer-spec.md` A6 은 `outline: 3px solid ocean-600`
offset 2px 를 요구한다. 실측 결과 **두 가지가 겹쳐 그 규칙이 거의 동작하지 않았다.**

### 2-1. 입력 필드에 표시가 아예 없었다

`inputClass` 의 `focus:outline-none` 이 전역 규칙을 끄고, 대체로 넣은
`focus:ring-4 focus:ring-ocean-100` 이 그려지지 않았다. 브라우저 계산값:

```
  --tw-ring-shadow: 0 0 0 calc(4px + 0px) #dbeefe        (설정됨)
  box-shadow:       rgba(0,0,0,0) 0 0 0 0  x5            (전부 투명)
```

### 2-2. 규칙이 레이어에 밀렸다

`:focus-visible` 규칙이 `@layer base` 안에 있어 Tailwind 유틸리티 레이어에 밀렸다.
`outline-color` 가 `currentColor` 로 되돌아가, 글자색이 흰색인 요소(선택된 칩·예산 기준
라디오)는 **흰 카드 위에 흰 아웃라인** 을 그렸다. `outline-offset` 도 0 으로 되돌아갔다.

규칙을 레이어 밖으로 옮겼다. 레이어 밖 선언은 모든 레이어를 이기므로, 컴포넌트가
클래스를 붙이는 걸 잊어도 표시가 조용히 사라지지 않는다.

### 2-3. 수정 후 실측

Tab 키 · 창 포커스 상태 · 전이 종료 후 측정. **실패 0건.**

| 요소 | outline | 배경 | 대비 |
|---|---|---|---|
| 건너뛰기 링크 | 3px ocean-600 offset 2px | 흰색 | 4.40 |
| 헤더 링크 | 〃 | 남색 그라디언트 | 3.74 |
| Hero CTA | 〃 | ocean-900 | 3.74 |
| 텍스트·날짜·숫자 입력 | 〃 | 흰색 | 4.40 |
| select · textarea | 〃 | 흰색 | 4.40 |
| 스타일 칩 (선택/미선택) | 〃 | 흰색 | 4.40 |
| 예산 기준 라디오 (선택/미선택) | 〃 | 흰색 | 4.40 |
| 푸터 링크 | 〃 | surface-subtle | 4.20 |

기준 WCAG 2.2 비텍스트 대비 3.0:1 — 11개 유형 전부 통과.

### 2-4. 측정 방법론 주의 (재현하려는 사람을 위해)

이 항목의 측정이 **세 번 틀렸다.** 원인 두 가지를 기록한다.

| 함정 | 증상 | 대응 |
|---|---|---|
| 창이 비활성 | `:focus-visible` 이 매칭되지 않아 전부 "표시 없음"으로 보인다 | `page.bringToFront()` |
| `transition` 이 걸린 요소 | Tab 직후 재면 전이 **시작값**(currentColor)을 읽는다 | Tab 후 260ms 대기 |
| JS `.focus()` | 버튼에서 `:focus-visible` 을 켜지 않는다 | 실제 Tab 키를 쓴다 |

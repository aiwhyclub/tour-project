## 1. 왜 푸터를 따로 설계하는가

footer.design은 푸터를 Typographic / Illustrative / Grid / Flat / Animated 형식, Bright / Dark 색조, Small / Large / Bold 타입 크기, Card-based 구조로 분류하는 큐레이션 갤러리다. 그 분류 체계가 성립한다는 사실 자체가 논지다 — **푸터는 분류할 만큼 설계 결정이 많은 표면**이고, 따라서 덧붙임으로 처리할 대상이 아니다.

PRD 5-2 "경험 품질 요구"의 **마무리** 항목("페이지 하단이 덧붙임이 아니라 의도적으로 설계된 마무리로 보인다")이 이 문서의 근거다.

### 1-1. 네 가지 분류 선택과 이유

| 축 | 선택 | 기각한 대안 | 이유 |
|---|---|---|---|
| 형식 | **Typographic** | Illustrative | 이 제품은 이미 상단에서 사진 시퀀스·3D로 시각 자극을 다 쓴다. 하단에서 또 그림을 쓰면 페이지가 양쪽 끝만 시끄러워진다. 대형 타이포는 자극 없이 마무리의 무게를 만든다 |
| 구조 | **Grid** | Card-based | 푸터 내용이 "링크 컬럼 + 고지 + 출처"로 이미 범주가 뚜렷하다. 카드로 또 나누면 결과 화면의 카드 분할과 경쟁한다 |
| 모션 | **Animated** | Flat | PRD 5-2 "조작 반응"과 일관성. 다만 **스크롤 진입 1회**로 제한한다. 루프 모션은 푸터에서 산만하다 |
| 색조 | **Bright** | Dark | Hero가 이 페이지의 **유일한** 어두운 면이다. 푸터까지 어둡게 하면 어두운 면이 콘텐츠를 위아래로 가두는 액자가 된다. `surface-subtle` 배경으로 결과 화면의 밝은 흐름을 그대로 닫는다 |
| 타입 크기 | **Large** | Small / Bold | 스테이트먼트는 크게(64px), 나머지는 작게(14–15px). 크기 대비 자체가 구조를 설명한다 |

## 3. B — 대형 타이포 스테이트먼트

### 3-1. 문안

```
예약도 결제도 하지 않습니다.
여행을 정하기 전에 필요한
초안 한 벌만 드립니다.
```

| 결정 | 이유 |
|---|---|
| 3행 고정 | 행 단위 마스크 리빌의 리듬을 만들기 위해 줄바꿈을 수동 제어한다 |
| 문안 내용 | 제품이 **하지 않는 것**을 먼저 말한다. 이 제품의 신뢰는 범위를 정확히 말하는 데서 나온다(R1·제외 범위). 마케팅 문구가 아니라 계약 문구다 |
| 마지막 행 강조 | "초안 한 벌"에 `accent-700` 적용 — 강조색 중 유일하게 텍스트로 안전한 값 (`surface-subtle` 배경 대비 **5.10**) |
| 금지 | "지금 바로 예약하세요" 류의 문구. 존재하지 않는 기능을 암시하면 S16 위반 |

### 3-2. 타이포

| 폭 | 크기 | line-height | letter-spacing | weight | 색 |
|---|---|---|---|---|---|
| ≥1440px | `clamp(2rem, 7vw, 4.5rem)` — 최대 **72px** | 1.1 | -0.03em | 800 | `ink` (대비 **17.06**) |
| 768–1439px | 48px (`text-h1`) | 1.15 | -0.025em | 700 | 동일 |
| <768px | **30px** (`text-h1` 모바일) | 1.25 | -0.025em | 700 | 동일 |

`text-wrap`을 쓰지 않는다. 3행 구조가 설계 의도이므로 `<span class="block">` 3개로 명시적으로 나눈다. 브라우저 자동 균형에 맡기면 폭에 따라 행 수가 변해 리빌 리듬이 무너진다.

390px에서 30px × `word-break: keep-all`로 각 행이 한 줄에 들어가는지 검증했다: "예약도 결제도 하지 않습니다." = 15자 × 약 21px ≈ 315px < 350px. ✅

>
> 실측: 1440px 에서 노출 링크 14개(컬럼 12 + 안내 영역 2), **전부 실제 요소로 해석**,

| 규칙 | 내용 |

## 5. 스크롤 진입 애니메이션

| 항목 | 값 |
|---|---|
| 트리거 | `ScrollTrigger` on `<footer>` · `start: 'top 88%'` · `once: true` |
| 정리 | `useGSAP` 컨텍스트 revert 시 자동 kill |
| 래핑 | 컴포넌트 `components/layout/SiteFooter.tsx` 내부 `useGSAP` |

### 5-1. `full` (≥768px, 모션 저감 아님)

| 순서 | 대상 | 값 | 시간 | 이징 | 지연 |
|---|---|---|---|---|---|
| 1 | 스테이트먼트 3행 | `clip-path: inset(100% 0 0 0)` → `inset(0% 0 0 0)` + `y 18 → 0` | 640ms | `expo.out` | 스태거 **0.08s** |
| 2 | 그리드 컬럼 4개 | `y 20 → 0`, `opacity 0 → 1` | 420ms | `expo.out` | 1 시작 +0.24s, 스태거 **0.12s** |
| 3 | 범위 고지 | `opacity 0 → 1` | 420ms | `power2.out` | 2 종료 시점 |
| 4 | 에셋 출처 | `opacity 0 → 1` | 420ms | `power2.out` | 3 시작 +0.08s |
| 5 | 하단 바 | `opacity 0 → 1` | 240ms | `power2.out` | 4 시작 +0.08s |

**총 길이 약 1.45s.** 마스크 리빌은 `clip-path`로 구현한다 — 행 아래에서 위로 밀려 올라오는 인상이 "마무리"에 맞다. `overflow: hidden` 부모 + `translateY` 조합은 `text-wrap`·`line-height`와 상호작용해 글자 위/아래가 잘리는 사고가 잦다.

### 5-2. `mobile` (<768px)

| 순서 | 대상 | 값 | 시간 | 스태거 |
|---|---|---|---|---|
| 1 | 스테이트먼트 3행 | `y 12 → 0`, `opacity 0 → 1` | 420ms | 0.06s |
| 2 | 아코디언 헤더 4개 | `opacity 0 → 1` | 300ms | 0.06s |
| 3 | 고지 + 출처 + 하단 바 | `opacity 0 → 1` | 300ms | 0 (동시) |

마스크 리빌을 쓰지 않는다. 30px 텍스트에서 `clip-path` 리빌은 효과가 거의 보이지 않으면서 페인트 비용만 든다.

### 5-3. `calm` (모션 저감)

애니메이션 없음. 전 요소가 최종 상태로 렌더된다. ScrollTrigger를 **생성하지 않는다** (matchMedia `calm` 분기에서 타임라인 코드에 진입하지 않음).

### 5-4. 초기 상태 안전장치

```ts
// ❌ 금지 — CSS로 숨기면 JS 실패 시 푸터가 영원히 사라진다
.footer-statement { opacity: 0; }

// ✅ gsap.from()으로 JS가 성공했을 때만 시작 상태를 만든다
gsap.from('.footer-statement > span', {
  clipPath: 'inset(100% 0 0 0)', y: 18, duration: 0.64,
  ease: 'expo.out', stagger: 0.08,
});
```

푸터는 라이선스 표기(R6)와 범위 고지를 담는다. **법적·윤리적 고지가 JS 실패로 사라지면 안 된다.** 이것이 초기 상태를 CSS에 두지 않는 가장 강한 이유다.

| 애니메이션 | `full`/`mobile`: `height` 240ms `power2.out`. `calm`: 즉시 |
| 터치 타깃 | `summary` 높이 48px |
| 접근성 | `<details>`가 `aria-expanded`를 브라우저가 관리한다. 수동 ARIA를 덧붙이지 않는다 |
| 데스크톱 | `<details open>`를 CSS로 강제하지 않고 **768px 이상에서는 `<details>`를 쓰지 않는 별도 마크업**을 렌더한다. `open` 속성 강제는 JS 없이 되돌릴 수 없다 |
